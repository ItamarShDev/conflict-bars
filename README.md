# ConflictBars

An interactive, bilingual timeline that places Israeli and Palestinian hip‑hop next to the conflicts it responds to. Built with Next.js (App Router), React 19, TypeScript and Tailwind CSS v4, with Convex for conflict/event data and song submissions.

## Project Goal

Document and visualize how the local hip‑hop scene intersects with conflicts and sociopolitical events. The timeline aims to:

- Give a chronological, two‑column view: conflicts on one side, songs and releases on the other.
- Offer neutral, sourced context — dates, lyric samples, links, and stated or reported political leanings.
- Work in English and Hebrew through locale‑aware routing.
- Let visitors submit songs or suggest corrections.

Entries should be concise, sourced, and neutral in tone. Eligibility rules and the data shape live in [AGENTS.md](./AGENTS.md) and [data/AGENTS.md](./data/AGENTS.md).

## Project Structure

- `data/<artist>/<era>.ts` — song records, the source of truth for songs (`90s.ts`, `2000s.ts`, `2010s.ts`, `2020s.ts`, plus an `index.ts` re‑export)
- `data/songs-generated.json` — build artifact produced from `data/`; git‑ignored, regenerated by `npm run generate-songs` (which `predev`/`prebuild` run automatically)
- `timeline/` — shared types (`types.ts`), conflict data (`conflicts.ts`, `conflict-utils.ts`), and the political‑leaning map (`artist-political-affiliation.ts`)
- `src/app/[lang]/` — the single locale‑aware route plus OG/Twitter images; `src/app/layout.tsx`, `globals.css`
- `src/components/timeline/` — `Timeline.tsx`, `YearSection.tsx`, `YearRail.tsx`, `SongEntry.tsx`, `FilterPanel.tsx`, `HelpModal.tsx`, `LanguageSwitcher.tsx`, `TimelineHeader.tsx`, `translations.ts` (en/he strings)
- `src/components/conflict/` — conflict card pieces; `src/components/SubmitSong*` — submission modal/form
- `src/utils/` — `file-songs.ts` (reads the generated JSON), `convex-helpers.ts`, `timeline.ts` (merges conflicts + songs by year), `colors.ts`
- `src/actions/email.ts` — server action that emails new submissions
- `convex/` — `schema.ts`, `events.ts`, `songs.ts`, `artists.ts`, `mutations.ts`
- `scripts/` — `generate-songs-json.ts`, migration/sync utilities

## Timeline Behaviour

`src/utils/timeline.ts` groups entries by year and the timeline renders the **union** of years that have a conflict and years that have a song, so a song from a year with no recorded conflict (e.g. 2003, 2019) still appears — its conflict column shows a neutral "no recorded conflict" note. Filters cover language, political leaning and conflict.

## Data Flow

```
data/<artist>/<era>.ts
  └─ scripts/generate-songs-json.ts   (recursively scans data/, skips index.ts)
       └─ data/songs-generated.json
            └─ src/utils/file-songs.ts → app/[lang]/page.tsx (server)
                                          + Convex events (preloadQuery)
                                             └─ src/utils/timeline.ts → Timeline
```

Songs render from the generated JSON; conflicts/events come from Convex. Because the generator walks the filesystem, adding or removing a song file changes the catalog — removing an artist means deleting their song files, not just their `index.ts` export.

## Local Development

1) Install dependencies

```bash
npm install
```

2) Start the Convex dev server (required — the timeline needs events)

```bash
npx convex dev
```

Keep this terminal running; it creates/connects the deployment, generates type‑safe API code, and watches `convex/`.

3) Seed Convex (first time only)

```bash
npm run migrate         # songs/artists
npm run migrate:events  # conflicts/events
```

4) Start Next.js

```bash
npm run dev             # runs generate-songs first
```

Open http://localhost:3000 — `/` redirects to `/he` (see `next.config.ts`); `/en` serves the English timeline.

## Content Model

### Song (file data)

```ts
{
  name: "Song Title (transliteration / translation)",
  artist: "Artist Name (native)",
  collaborators?: string[],
  language?: "Hebrew" | "Arabic" | "English" | "Hebrew/Arabic" | ...,
  published_date: "YYYY" | "YYYY-MM" | "YYYY-MM-DD",
  lyric_sample?: { hebrew?: string; english_translation?: string },
  links?: { lyrics?: string; song_info?: string; youtube?: string },
}
```

`published_date` is parsed with `new Date()`, so decade placeholders like `"2020s"` do not render — always use a real year.

### Political leaning

`timeline/artist-political-affiliation.ts` maps the exact `artist` string to `{ era, affiliation, notes }`. The key must match the song's `artist` value verbatim, otherwise the entry falls back to the "unknown" grey border.

### Convex

- `songs` — submitted songs, hydrated with artist/collaborators (`convex/songs.ts`)
- `events` — conflicts with dates, descriptions and effects (`convex/events.ts`)
- `song_edit_suggestions` — visitor corrections (`convex/mutations.ts`)

Manage data at https://dashboard.convex.dev

## Internationalization

The locale is a route segment: `src/app/[lang]/` handles `en` and `he`, and `next.config.ts` redirects `/` to `/he`. UI strings live in `src/components/timeline/translations.ts` — add both `en` and `he`.
